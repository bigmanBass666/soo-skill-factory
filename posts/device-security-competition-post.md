# 【Skill 创作】TRAE 账号安全管家 —— 多设备登录风控诊断与一键反馈全流程 Skill

## 一、Skill 简介

**名称**：`trae-device-security`（TRAE 账号安全管家）

**一句话说明**：管理你的多设备登录状态、诊断风控限制、一键生成论坛反馈帖并自动发布到 TRAE 社区。

**解决什么问题**：

TRAE 限制单账号最多 **2 台设备同时登录**，超出后触发 **24 小时风控机制**，用户会看到提示语：

> "今天先到哪里也不错。好好休息下，明天再继续吧~"

但官方目前 **没有设备管理功能** —— 用户无法查看已登录设备列表，无法远程退出其他设备，甚至无法判断自己到底触碰了哪条红线（设备超限？额度耗尽？行为异常？）。

本 Skill 将 **设备追踪 → 风控预警 → 智能诊断 → 反馈帖生成 → 论坛自动发布** 全流程封装为一个可复用的 SOLO Skill，让每个 TRAE 用户都能从容应对账号安全问题。

## 三、核心功能演示

本 Skill 包含 **4 大模块**，覆盖从预防到应对的完整链路。

### 模块 A：设备登录记录与追踪

通过 `~/.trae/device-log.json` 持久化管理你的设备登录状态，内置 `device-log.sh` 脚本提供 CLI 操作能力。

**使用示例**：

```bash
# 初始化设备日志
./scripts/device-log.sh init

# 记录新设备
./scripts/device-log.sh add "我的MacBook Pro"
# 输出: ✓ 设备已添加 (第 1 条记录)
#   设备名:   我的MacBook Pro
#   主机名:   macbook-pro-m1
#   操作系统: Darwin
#   IP 地址:  192.168.1.100
#   登录时间: 2026-05-12T10:30:00Z

# 查看所有设备（自动标注风险）
./scripts/device-log.sh list
# 当设备数 ≥ 2 时自动警告: ⚠ 超过安全阈值 (>=2)
```

**输出效果**（Markdown 格式表格）：

```
📋 设备登录清单
生成时间：2026-05-12T10:30:00Z  |  总计：3 台设备

#  主机名           系统        最后活跃              状态      标签
1  macbook-pro-m1    macOS 15.3  2026-05-12T08:15:00Z  ✅ active  home, primary
2  office-desktop    Ubuntu     2026-05-10T09:00:00Z  ⚠️ inactive  office
3  cyber-cafe-pc     Windows 11 2026-05-08T14:20:00Z  🔴 public   temporary
```

> 💡 `public` / `temporary` 标签的设备会被高亮提醒优先清理。

### 模块 B：风控预警与智能诊断

当检测到风控关键词时，自动触发分级预警（🔴严重 / 🟡警告 / 🟠提醒），并生成完整的诊断报告。

**使用示例**：

> 用户输入："我之前在外地出差，在几台公用电脑上登录了 trae ide 账户，现在回来了，我想退出那几台电脑的登录。但是现在我可能因为同时登陆了多台设备而遇到了'今天先到这里也不错。好好休息下，明天再继续吧~'的报错"

**Skill 自动输出**（摘要版）：

```
🔒 TRAE 账号安全诊断报告
━━━━━━━━━━━━━━━━━━━━━━━
风险等级：🔴 严重 (CRITICAL)

触发原因判定：
├── ✅ 今天是否在 ≥3 台设备上登录过？→ 是 → 【设备超限】
├── ✅ 是否短时间频繁切换？→ 是 → 【行为风控】
└── 🎯 综合判定：【设备超限 + 行为风控】双重触发

解决方案（4 种）：
├── 方案 A：等待 24h 自动解除（成功率 ~100%）⭐ 推荐
├── 方案 B：全部设备退出后重登（40-60%）
├── 方案 C：清除 Cookie 后重试（20-30%）
└── 方案 D：联系官方客服（紧急情况）

引用社区数据：#12293 #13482 #11941 #15885 #16802 #16852
```

报告包含完整的时间线、设备清单、行动路线图和 12 条快速行动清单。（[完整报告样例见 eval 输出](https://github.com/user/trae-device-security/blob/main/evals/eval-1-with-skill-output.md)）

### 模块 D：论坛自动化发帖（Playwright MCP）

通过 Playwright MCP 实现从内容生成到论坛发布的端到端自动化。

**工作流**：

```
模块 C 生成帖子内容
    ↓
Step 1: 打开 https://forum.trae.cn
    ↓
Step 2: 验证登录态（未登录则暂停引导）
    ↓
Step 3: 选择目标板块（产品建议→功能建议 / 求助→帮助与支持）
    ↓
Step 4: 填写标题 + 正文（处理富文本兼容性）
    ↓
Step 5: 截图预览 → 用户确认
    ↓
Step 6: 点击发布 → 返回帖子 URL
```

**失败回退机制**：Playwright 不可用时自动降级为保存草稿到 `~/trae-drafts/` 并提示手动发布。

## 四、技术实现亮点

### 4.1 SKILL.md 结构设计：Progressive Disclosure（渐进式披露）

SKILL.md 采用 **4 层递进式结构**，兼顾新手易用性和专家深度需求：

```
Layer 1: Skill 概述 + 触发场景列表（10 个场景，覆盖所有入口）
    ↓
Layer 2: 四大模块详细定义（A/B/C/D，每个模块独立闭环）
    ↓
Layer 3: 输出格式规范（3 种标准格式模板）
    ↓
Layer 4: 最佳实践知识库（6 条经验法则 + 命令速查表）
```

**设计原则**：
- **frontmatter description 采用 "pushy" 策略**：覆盖 10+ 触发信号关键词，确保高召回率
- **模块化设计**：A/B/C/D 四个模块可独立调用，也可组合使用（如 B→C→D 诊断→发帖→发布全链路）
- **模板驱动**：每种输出都有严格的格式模板，保证一致性

### 4.2 references/ 数据驱动架构

Skill 不依赖硬编码的知识，而是通过 `references/` 目录引入外部数据源：

```
references/
├── forum-data.md      # 6 个社区关键帖子的完整数据引用库
│                       # 含：帖子编号/标题/回复数/核心结论/引用优先级
└── best-practices.md   # 6 大最佳实践完整指南
                        # 含：原理说明/操作步骤/常见误区/进阶技巧
```

**为什么这样设计**：
- **数据可更新**：当论坛有新帖子时，只需更新 `forum-data.md`，无需改 SKILL.md
- **知识可复用**：best-practices.md 可独立作为用户手册使用
- **来源可追溯**：每个结论都标注了原始帖子链接，增强可信度

### 4.3 Playwright MCP 深度集成

模块 D 将浏览器自动化无缝嵌入 Skill 工作流：

- **智能回退**：5 种失败场景各有对应的回退策略（保存草稿/手动指引/重试机制）
- **板块映射表**：自动根据帖子类型选择正确的目标板块
- **发布前确认**：截图预览 + 用户确认，避免误发

## 五、效果对比（Benchmark 数据）

使用 **3 组 Eval 测试用例** 对 Skill 进行了系统性评估，每组测试用例分别在 **with_skill** 和 **without_skill**（baseline）两种配置下运行。

### 评估方法

| Eval ID | 场景 | Prompt | 评估维度 |
|---------|------|--------|----------|
| eval-1 | 风控诊断 | 出差公用电脑登录后被风控锁死 | 5 项断言 |
| eval-2 | 反馈帖生成 | 生成设备管理功能的产品建议帖 | 6 项断言 |
| eval-3 | 安全检查 | 检查 TRAE 账号安全状态 | 5 项断言 |

### Benchmark 结果

| 场景 | with_skill | without_skill | 提升 |
|------|-----------|-------------|------|
| **eval-1 风控诊断** | **100%** ✅ (5/5) | 80% (4/5) | **+20%** |
| **eval-2 反馈帖生成** | 66.7% (4/6) | 66.7% (4/6) | 持平 |
| **eval-3 安全检查** | **100%** ✅ (5/5) | 40% (2/5) | **+60%** 🏆 |
| **平均通过率** | **88.9%** | 62.2% | **+26.7%** |

### 关键发现

#### 🔥 eval-3 安全检查：最大差异场景（+60%）

**without_skill 的表现**：AI 将"TRAE 账号安全"误解为"操作系统安全"，输出了防火墙、端口扫描等完全不相关的内容 ❌

**with_skill 的表现**：准确理解上下文，输出了设备限制分析、风控风险评估、基于社区数据的操作建议 ✅

> 这说明：**没有 Skill 引导时，AI 容易泛化到错误方向；Skill 的领域知识是核心差异化能力。**

#### 📊 eval-1 风控诊断：社区数据引用是杀手锏（+20%）

**with_skill** 的诊断报告中引用了 **6 个论坛帖子编号及链接**，而 **without_skill** 完全没有任何社区数据支撑。这使得 with_skill 的报告具有可验证性和权威性。

#### ⚠️ eval-2 反馈帖：待优化点（持平）

两组在 P0/P1/P2 格式组织上都有缺失。这是 **Iteration 2 的重点优化方向** —— 在 SKILL.md 模块 C 中加强格式约束。
