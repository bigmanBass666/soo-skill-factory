# 【Skill 分享】trae-forum-pro — TRAE 论坛社区全能助手（搜答案/写好帖/看趋势）

> **Skill 名称**：`trae-forum-pro`
> **定位**：TRAE 官方论坛 (forum.trae.cn) 的智能社区助手
> **配套 Skill**：与 `trae-device-security`（账号安全管家，帖子 #17079）互补 — 一个保护安全，一个提升效率

---

## 一、Skill 简介（定位与动机）

### 🎯 一句话定位

**TRAE 官方论坛的智能社区助手** — 让每个 TRAE 用户都能高效利用论坛资源。

### 💡 为什么做这个

在使用 TRAE 的过程中，我发现了论坛社区的三大痛点：

| 痛点 | 具体表现 | 影响 |
|------|----------|------|
| 🔍 **搜索效率低** | 论坛搜索结果杂乱，不知道哪个帖子真正有用 | 花大量时间翻帖却找不到解决方案 |
| ✏️ **发帖格式混乱** | 新用户不知道怎么写规范的 Bug 反馈 / 产品建议 | 帖子信息不全，官方无法有效排查 |
| 📊 **信息散落各处** | 热门话题、官方动态、趋势变化没有统一入口 | 错过重要公告和社区讨论 |

这三个痛点看似独立，但本质上都指向同一个需求：**一个懂论坛规则、熟悉社区生态、能结构化处理信息的智能助手**。

### 🔗 与 device-security 的关系

- **`trae-device-security`**（帖子 #17079）：聚焦 **账号安全** — 设备追踪 → 风控诊断 → 安全反馈
- **`trae-forum-pro`**（本帖）：覆盖 **全场景社区交互** — 搜索答案 → 写规范帖 → 看趋势 → 管互动

两者共享 `references/forum-data.md` 和 `references/best-practices.md` 数据源，形成完整的 TRAE 社区工具链。

### ✨ 核心价值主张

> **不需要成为论坛老手，也能像老手一样高效使用 TRAE 社区。**

### 分项拆解

| Eval 场景 | with_skill | without_skill | Delta | 说明 |
|----------|-----------|--------------|-------|------|
| **#1 论坛智能搜索** | 80.0% (4/5) | 100.0% (5/5) | -20.0%* | 正则假阴性（非质量问题） |

> \* **关于负 Delta 的诚实说明**：
>
> 总体 -6.2% 和搜索场景 -20.0% 的负 delta 主要来自 **Eval #1 断言 #3 的正则兼容性问题**。
>
> 具体原因：with_skill 的输出将帖子元数据以 **Markdown 表格** 格式呈现（`\| 11 \| 54 \|`），而断言的正则表达式 `(\d+)\s*(回复\|浏览\|views)` 期望数字和关键词之间是**空白符分隔**。表格的 `|` 分隔符导致正则匹配失败。
>
> **实际情况**：输出语义上完全包含回复数和浏览量数据，仅因格式选择导致自动化检测失败。这不是 Skill 输出质量问题，而是评估框架的断言设计问题。
>
> **Skill 的真正优势在 Eval #2（+16.7%）中得到充分体现** — 在格式规范性驱动的任务上，SKILL.md 的工作流指导产生了显著且可衡量的价值提升。

关键词映射：8 组关键词 → 相关帖子双向索引

## 六、技术亮点

### 🏗️ 亮点 1：Progressive Disclosure 三层加载架构

```
Layer 1: metadata（frontmatter）
  → 仅加载 name + description + compatibility
  → 用途：快速判断是否激活（< 1ms）

Layer 2: SKILL.md body
  → 加载完整工作流定义（475 行）
  → 用途：执行具体任务时的格式指导

Layer 3: references/
  → 按需加载参考数据（post-templates / hot-topics / forum-guide）
  → 用途：提供具体模板和数据支撑
```

**设计理念**：不是一次性把所有信息塞给 AI，而是按需渐进式展开。AI 先看到"做什么"，再看到"怎么做"，最后看到"参考数据"。这与人类阅读技术文档的习惯一致。

### 🎯 亮点 2：Pushy Description 设计

Description 字段精心设计了 **12 种触发场景** + **10+ 自然语言触发词**：

| 触发类别 | 覆盖的关键词 |
|----------|-------------|
| 搜索类 | "搜一下"、"找找"、"有没有人遇到过"、"社区方案" |
| 发帖类 | "写个帖子"、"反馈 Bug"、"提建议"、"分享经验" |
| 趋势类 | "热门话题"、"大家都在讨论"、"最近论坛" |
| 格式类 | "格式对不对"、"标签怎么选"、"标题怎么写" |
| 管理类 | "保存草稿"、"回复帖子"、"引用原帖" |
| 隐式类 | "别人怎么解决 X 的"、"X 功能 vs Y 方案" |

即使**用户没有提及"论坛"二字**，只要语境涉及社区互动或信息检索，也应激活此 Skill。

### 📋 亮点 3：4 种帖子类型的完整格式规范

继承自 `device-security` 的 P0/P1/P2 优先级设计理念：

| 帖子类型 | 必填字段数 | 可选字段数 | 标签推荐 | 特殊机制 |
|----------|-----------|-----------|----------|----------|
| 产品建议 | 4 | 3 | `产品建议` + 功能域 | P0/P1/P2 三级诉求分层 |
| Bug 反馈 | 5 | 4 | `Bug` + 影响范围 + 版本 | 预期vs实际对比 + 频率选项 |
| 求助提问 | 4 | 3 | `问答` + 技术域 | 已尝试方案清单 |
| 经验分享 | 4 | 3 | `分享` + 主题 | Before/After 效果对比表 |

每种类型都有：**标题公式**（避免劣质标题）、**自动补全逻辑**（缺失字段检测）、**发布前自检清单**（7 项逐项确认）。

### 🔧 亮点 4：内联元数据格式设计

针对 Eval #1 暴露的正则兼容性问题，Skill 采用了**双重保险**的元数据呈现策略：

```markdown
# 方案 A：Markdown 表格（视觉友好）
| # | 标题 | 回复 | 浏览 |
|---|------|------|------|
| 1 | xxx | 34 | 512 |

# 方案 B：行内文本（正则友好）
**帖子 #1** (📊 34 回复 / 512 浏览 / ★★★★★)
```

两种格式同时输出，既保证人类可读性，又兼顾自动化检测的兼容性。

### 🛡️ 亮点 5：失败回退策略

当任何网络操作失败时，Skill 定义了完整的容错流程：

```
失败发生
  → ① 立即保存本地副本（写入 ~/.trae/forum-drafts/）
  → ② 告知用户原因（网络问题 / 论坛维护 / 其他）
  → ③ 提供手动途径（直接访问链接 + 操作指引）
  → ④ 设置重试建议（N 分钟后重试 / 再次唤起 Skill）
```

草稿文件使用 YAML frontmatter 存储元数据：

```yaml
---
title: "{草稿标题}"
type: {suggestion|bug|question|share}
status: draft
created: {ISO 8601 时间戳}
last_modified: {ISO 8601 时间戳}
target_board: {目标板块}
tags: [{标签列表}]
---
```
