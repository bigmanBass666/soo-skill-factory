# TRAE 论坛完整使用指南

> 本指南面向所有 TRAE 论坛新用户，帮助你快速熟悉论坛结构、发帖规范和社区文化。

---

## 一、论坛概览

TRAE 官方论坛（https://forum.trae.cn/）是 TRAE IDE 用户的核心交流平台，承载以下三大职能：

| 职能 | 说明 |
|------|------|
| **用户帮助** | 解决使用过程中遇到的各种问题，获取官方和社区的解答 |
| **产品反馈** | 提交功能建议、Bug 报告，直接影响产品迭代方向 |
| **社区交流** | 分享使用经验、参与技术讨论、结识志同道合的开发者 |

论坛采用 Discourse 引擎构建，支持 Markdown 富文本编辑、实时通知、话题标签、用户等级等现代化社区功能。

## 二、版块结构详解

### 2.1 产品建议区 (`/c/8-category/8`)

- **定位**：收集用户对 TRAE 功能的新需求与改进意见
- **适合内容**：功能请求、体验优化建议、竞品对比分析
- **注意事项**：发帖前请先搜索是否已有类似建议，可在已有帖子下补充讨论
- **典型帖子**：「希望增加多光标编辑支持」「建议优化大型项目索引速度」

### 2.2 Bug 反馈区

- **定位**：集中报告软件缺陷、崩溃、异常行为等问题
- **适合内容**：可复现的错误、性能问题、兼容性故障
- **注意事项**：务必提供完整的复现步骤和环境信息（见后文模板）
- **典型帖子**：「保存文件时偶尔闪退」「AI 补全在某些语言下不生效」

### 2.3 帮助与支持区 (`/c/7-category/7`)

- **定位**：新手求助、操作疑问、配置问题解答
- **适合内容**："如何做 X" 类问题、安装部署问题、快捷键查询
- **注意事项**：问题描述越具体，获得有效回复的概率越高
- **典型帖子**：「如何配置 Python 解释器？」「Git 集成报错怎么处理？」

### 2.4 综合讨论区

- **定位**：自由交流空间，不限特定主题
- **适合内容**：开发经验分享、行业动态、工具推荐、闲聊水贴（适度）
- **注意事项**：保持内容与技术/开发相关，避免纯广告或无关话题
- **典型帖子**：「我的 TRAE 工作流分享」「2025 年 AI 编程工具趋势」

### 2.5 公告区

- **定位**：官方发布产品更新、活动通知、政策变更的唯一渠道
- **特点**：仅管理员可发帖，普通用户只能回复
- **建议**：定期浏览公告区，第一时间掌握产品动态

### 2.6 SOLO 技能创作赛 (`/c/37-category/37`)

- **定位**：TRAE SOLO Skill 创作与分享的专题板块
- **适合内容**：原创 Skill 发布、Skill 使用心得、创作技巧交流
- **特色**：定期举办官方赛事，优秀作品可获得奖励和曝光
- **典型帖子**：「我写了一个自动生成单元测试的 Skill」「Skill 创作入门教程」

### 版块速查表

| 版块 | 路径 | 发帖权限 | 主要用途 |
|------|------|----------|----------|
| 产品建议 | `/c/8-category/8` | 所有用户 | 功能请求 |
| Bug 反馈 | Bug 板块 | 所有用户 | 问题报告 |
| 帮助与支持 | `/c/7-category/7` | 所有用户 | 求助问答 |
| 综合讨论 | 综合区 | 所有用户 | 自由讨论 |

| SOLO 技能赛 | `/c/37-category/37` | 所有用户 | Skill 分享 |

## 三、发帖规则与礼仪

### 3.1 核心原则

1. **搜索后再发帖**
   - 使用论坛顶部搜索框，输入关键词检查是否已有类似讨论
   - 在已有热帖中追加你的情况，比开新帖更有价值
   - 重复帖子可能会被合并或关闭

2. **标题要具体明确**
   - 好：「Mac 上 TRAE v2.1 启动时白屏 10 秒后崩溃」
   - 差：「有个问题」「求助！！！」「Bug」
   - 标题应包含：[环境] + [现象] + [关键词]

3. **提供完整信息**
   - 环境信息：操作系统版本、TRAE 版本、项目类型
   - 复现步骤：从打开软件到出现问题的每一步操作
   - 期望 vs 实际：你期望发生什么 vs 实际发生了什么

4. **尊重他人**
   - 不同意观点时针对事不对人
   - 新手提问耐心引导，不要嘲讽
   - 官方人员回复时给予理解和配合

5. **禁止行为**
   - 灌水刷屏（无意义短回复连续发布）
   - 发布广告、垃圾链接、违规内容
   - 人身攻击、引战言论
   - 泄露他人隐私信息

### 3.2 回复礼仪

- **点赞代替「+1」**：如果只是表示认同，点击点赞按钮即可
- **引用精准**：回复时只引用相关段落，不要全文引用
- **标记解决**：问题解决后在帖子中标记，方便后续用户查阅
- **感谢帮助者**：获得有效帮助后，一句感谢能激励更多人参与

## 四、帖子类型格式规范详解

### 4.1 产品建议类帖子

#### 必填字段

| 字段 | 说明 | 示例 |
|------|------|------|
| 标题 | 以【产品建议】开头 | 【产品建议】增加终端分屏功能 |
| 痛点场景 | 具体描述遇到的问题 | 每次需要同时查看日志和运行命令... |
| 解决方案 | 你期望的功能形态 | 支持左右/上下分割终端面板... |
| 影响范围 | 受影响人群估计 | 团队开发场景中约 60% 用户有此需求 |

#### 推荐格式

```markdown
## 【产品建议】【简明标题】

### 痛点场景
[具体描述]

### 期望方案
- 核心功能点 A
- 辅助功能点 B

### 参考案例
> [竞品或其他工具的实现方式]

### 补充
[截图、数据等]
```

### 4.2 Bug 反馈类帖子

#### 必填字段

| 字段 | 说明 | 示例 |
|------|------|------|
| 标题 | 以【Bug】开头 + 简明描述 | 【Bug】保存文件后界面卡死 5 秒 |
| 环境信息 | OS / TRAE 版本 / 项目类型 | macOS 14.0 / TRAE 2.1.0 / React 项目 |
| 复现步骤 | 可操作的步骤列表 | 1. 打开项目 → 2. 编辑文件 → ... |
| 期望结果 | 正常情况下应发生什么 | 文件保存成功，界面正常响应 |
| 实际结果 | 实际发生的异常 | 界面无响应约 5 秒后恢复 |
| 附件 | 截图/日志/录屏 | 控制台错误截图链接 |

#### 推荐格式

```markdown
## 【Bug】【简明标题】

### 环境信息
| 项目 | 值 |
|------|-----|
| 操作系统 | [OS 名称及版本] |
| TRAE 版本 | [版本号] |
| 项目类型 | [语言/框架] |

### 复现步骤
1. [第一步]
2. [第二步]
3. [第三步]

### 期望结果
[正常行为描述]

### 实际结果
[异常行为描述]

### 附加信息
- 截图：[链接]
- 日志片段：
```log
[粘贴关键日志]
```
```

### 4.3 求助提问类帖子

#### 必填字段

| 字段 | 说明 |
|------|------|
| 标题 | 以【求助】开头 + 具体问题 |
| 已尝试方法 | 你已经试过的解决方案 |
| 相关截图/代码 | 能说明问题的可视化材料 |
| 期望答案形式 | 需要步骤指导/配置示例/原理解释 |

### 4.4 经验分享类帖子

#### 必填字段

| 字段 | 说明 |
|------|------|
| 标题 | 以【分享】开头 + 主题 |
| 适用场景 | 这个经验在什么情况下有用 |
| 详细步骤/方法 | 核心内容的完整说明 |
| 效果对比 | 使用前后的差异（可选） |
| 注意事项 | 可能的坑或限制条件 |

## 五、Markdown 格式要求

### 5.1 基础语法速查

| 用途 | 语法 | 效果 |
|------|------|------|
| **粗体** | `**文本**` | **粗体** |
| *斜体* | `*文本*` | *斜体* |
| ~~删除线~~ | `~~文本~~` | ~~删除线~~ |
| 行内代码 | `` `代码` `` | `code` |
| 代码块 | ``` 包裹 | 高亮代码块 |
| 引用 | `>` 开头 | 引用块 |
| 无序列表 | `-` 或 `*` 开头 | 列表项 |
| 有序列表 | `数字.` 开头 | 编号列表 |
| 表格 | `\|` 分隔 | 对齐表格 |
| 链接 | `[文字](URL)` | 可点击链接 |
| 图片 | `![alt](URL)` | 嵌入图片 |
| 标题 | `#` ~ `######` | H1 ~ H6 |

### 5.2 代码块规范

- 始终指定语言标识以启用语法高亮：

````markdown
```python
def hello():
    print("Hello, TRAE!")
```
````

- 日志输出使用 `log` 或 `text` 标识
- 终端命令使用 `bash` 标识
- 配置文件根据格式选择 `json` / `yaml` / `toml`

### 5.3 表格规范

- 表头使用 `|` 分隔各列
- 第二行用 `|---|---|` 定义对齐方式（左对齐 `:---`，右对齐 `---:`，居中 `:---:`）
- 单元格内不支持嵌套复杂 Markdown，保持简洁

### 5.4 标签使用规范

- 每个帖子添加 **2-5 个标签**
- 优先使用已有标签（输入时会有自动补全提示）
- 标签格式：中文标签用中文，技术术语可用英文
- 示例：`bug`, `ai-completion`, `macOS`, `性能问题`, `v2.1`

## 六、常见 FAQ

### Q1：如何快速找到答案？

**A：** 三步走策略：
1. **搜索框优先**：在论坛首页顶部的搜索栏输入关键词（建议中英文都试试）
2. **按板块筛选**：确定问题类型后进入对应板块浏览置顶帖和精华帖
3. **Google 站内搜索**：使用 `site:forum.trae.cn 关键词` 可以搜到更全面的结果

> 小技巧：搜索时尽量用名词而非动词，比如搜「多设备限制」比「怎么登录两个设备」效果更好。

---

### Q2：我的帖子为什么没人回复？

**A：** 常见原因及改进方法：

| 原因 | 改进措施 |
|------|----------|
| 标题太模糊 | 改为包含具体症状的描述性标题 |
| 信息不全 | 补充环境信息、复现步骤、截图 |
| 发错板块 | 移动到正确的分类下 |
| 问题是极个别案例 | 说明你已尝试的排查方向 |
| 帖子刚发布 | 耐心等待 24-48 小时，社区成员分布在全球时区 |

---

### Q3：如何写一个有效的 Bug 反馈？

**A：** 一个高质量的 Bug 反馈 = **可复现** + **信息完整** + **描述清晰**。核心要素：

1. **环境信息不能省**：操作系统精确到小版本号，TRAE 版本号完整写出
2. **复现步骤要傻瓜化**：假设读者完全不了解你的项目，从零开始也能照着做出来
3. **区分事实和猜测**：客观描述观察到的现象，不要混入你认为的原因
4. **提供证据**：截图、日志片段、录屏链接都比纯文字更有说服力
5. **给出最小复现**：如果可能，剥离掉无关因素，提供最简单的复现路径

---

### Q4：产品建议被采纳的几率？

**A：** 采纳率取决于多个维度：

- **需求普遍性**：影响用户越多，优先级越高（团队协作 > 个人偏好）
- **实现可行性**：技术上可行且投入产出比合理
- **讨论热度**：高赞、高回复的建议更容易被产品团队关注
- **与路线图一致性**：符合当前产品规划方向的建议推进更快

> 即使暂时未被采纳，高质量的建议也会被记录在需求池中，后续版本可能排期实现。

---

### Q5：怎样参与官方活动？

**A：** 关注以下渠道：

1. **公告区置顶帖**：所有官方活动的正式通知会在此发布
2. **SOLO 技能创作赛板块**：技能相关的赛事专门区域
3. **帖子标签**：关注 `官方活动` 标签下的帖子
4. **社区活跃度**：经常互动的用户可能会收到定向邀请

参与方式通常包括：提交作品、发帖讨论、投票评选等，具体规则见各活动公告。

---

### Q6：帖子可以编辑吗？删除呢？

**A：**

| 操作 | 规则 | 说明 |
|------|------|------|
| 编辑 | 发帖后一定时间内可自由编辑 | 超过时间窗口需联系管理员 |
| 删除 | 自行删除有时间限制 | 帖子有回复后通常不可自行删除 |
| 归档 | 旧帖会被自动归档 | 不影响内容查看，但无法再回复 |

> 建议：发帖前预览确认无误后再发布，重要修改可通过编辑完成。

---

### Q7：如何关注特定话题？

**A：** 多种追踪方式：

- **订阅板块**：进入感兴趣的板块，点击右上角通知图标设置接收频率
- **关注标签**：在标签页面点击「关注」，该标签下的新帖会推送给你
- **收藏帖子**：对重要帖子点击书签图标，随时可以在个人中心找到
- **@提醒**：在帖子中 @某人，对方会收到通知（慎用，避免骚扰）

---

### Q8：官方回复一般需要多久？

**A：** 时间因问题类型而异：

| 问题类型 | 通常响应时间 | 说明 |
|----------|-------------|------|
| 紧急 Bug（影响大量用户） | 24-48 小时 | 可能加急处理并发布 hotfix |
| 一般 Bug | 3-7 个工作日 | 排入迭代队列 |
| 产品建议 | 1-2 周 | 需要评估和内部讨论 |
| 使用求助 | 取决于社区活跃度 | 社区用户可能比官方更快回答 |

> 提示：非紧急问题避免在周末或节假日催促，给官方团队合理的处理时间。同时，很多问题热心社区成员就能解答，不必非要等官方回复。
