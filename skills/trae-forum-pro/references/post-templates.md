# TRAE 论坛帖子模板库

> 一套即开即用的发帖模板，覆盖论坛四大主要帖子类型。复制模板后替换 `[占位符]` 即可快速发布高质量帖子。

---

## 一、产品建议模板

```markdown
## 【产品建议】[简明标题，20字以内]

### 痛点场景
[描述你在什么情况下遇到这个问题，越具体越好。包含：使用频率、触发条件、当前 workaround]

> 示例：每天在 TRAE 中开发 React 项目时，需要同时查看组件代码和终端运行日志。目前只能在编辑器和终端之间来回切换窗口，打断编码思路。

### 影响范围
- 受影响用户规模：[估计人数或比例，如「团队中约 70% 的前端开发者」]
- 影响频率：[每次使用 / 偶尔 / 特定场景下必然出现]
- 相关社区讨论：[引用已有帖子编号，如「参见 #18105 的讨论」]

### 解决方案
- **P0（必须要有）**：[最核心的功能点，没有它问题无法解决]
- **P1（应该有）**：[重要但非紧急的改进，能显著提升体验]
- **P2（可以有）**：[锦上添花的功能，有更好没有也能接受]

### 预期效果
[描述实现后的用户价值，尽量量化。如：「预计减少 40% 的窗口切换操作」「团队代码审查效率提升约 30%」]

### 参考案例
> [竞品或其他工具的实现方式，附截图或链接更佳]

### 补充信息
- 截图/录屏：[链接]
- 数据支撑：[如有调研数据或用户反馈统计]
- 其他想法：[任何补充说明]
```

```markdown

### 环境信息
| 项目 | 值 |
|------|-----|
| 操作系统 | [如 macOS 14.4.1 / Windows 11 23H2 / Ubuntu 22.04 LTS] |
| TRAE 版本 | [在 帮助 → 关于 中查看完整版本号] |
| 项目类型 | [如 React + TypeScript / Python Django / Go 微服务] |
| Node.js / Python 版本 | [运行时版本，如适用] |
| 其他相关工具 | [Git 版本、扩展插件等] |

### 复现步骤
1. [打开 TRAE，创建/打开一个 XXX 项目]

> 请确保每一步都可以独立复现，避免「有时候会出现」这类模糊描述。

### 期望结果
[正常情况下应该发生什么。如：「文件保存成功，编辑器界面无卡顿」]

### 实际结果

### 出现频率

- [ ] 经常出现（>50%）
- [ ] 偶尔出现（<50%）
- [ ] 仅一次，无法重现

### 附加信息
- **截图**：[上传截图或粘贴链接]
- **控制台日志**：
```log
[在此粘贴关键错误日志，使用 log 代码块]
```
- **录屏演示**：[Loom / 屏幕录制链接]
- **已尝试的解决方法**：
  - [ ] 重启 TRAE
  - [ ] 清除缓存
  - [ ] 禁用所有插件后重试
  - [ ] 在新项目中复现
  - [ ] 其他：[描述]

## 五、Markdown 格式技巧

### 5.1 表格语法

#### 基础表格

```markdown
| 列1 | 列2 | 列3 |
|-----|-----|-----|
| A   | B   | C   |
| D   | E   | F   |
```

#### 对齐方式

```markdown
| 左对齐 | 居中 | 右对齐 |
|:------|:----:|------:|
| 文本  | 文本 | 文本  |
```

#### 表格内格式

- 单元格内可用 `**粗体**`、`` `代码` ``、`[链接](url)`
- 单元格内换行使用 `<br>` 标签
- 不支持嵌套表格或复杂 Markdown

### 5.2 代码块

#### 基础语法高亮

````markdown
```python
def greet(name: str) -> str:
    return f"Hello, {name}!"
```
````

#### 支持的语言标识

| 标识符 | 用途 | 标识符 | 用途 |
|--------|------|--------|------|
| `python` | Python | `javascript` / `js` | JavaScript |
| `typescript` / `ts` | TypeScript | `java` | Java |
| `go` | Go | `rust` | Rust |
| `cpp` / `c++` | C++ | `c` | C |
| `bash` / `sh` | Shell 命令 | `json` | JSON 数据 |
| `yaml` / `yml` | YAML 配置 | `toml` | TOML 配置 |
| `sql` | SQL 查询 | `html` | HTML |
| `css` | CSS 样式 | `xml` | XML |
| `log` | 日志输出 | `text` | 纯文本（无高亮） |

#### 行内代码

- 短代码片段使用反引号：`` `const x = 1` ``
- 文件路径：`` `/usr/local/bin/trae` ``
- 快捷键说明：`` `Cmd + Shift + P` ``

### 5.3 引用层级

```markdown
> 一级引用（普通引用）
>
> 二级引用（嵌套引用）
>
>> 三级引用（最多嵌套两层为宜）
```

**注意**：Discourse 引用嵌套超过 3 层会影响阅读体验，建议控制在 2 层以内。

### 5.4 图片插入

#### 外链图片

```markdown
![图片说明](https://example.com/image.png)
```

#### 本地图片（拖拽上传）

在编辑器中直接拖拽图片文件即可自动上传并生成链接。支持格式：PNG、JPG、GIF、WebP。

#### 图片尺寸控制

```markdown
<img src="URL" width="600">
```

### 5.5 列表样式

#### 无序列表

```markdown
- 第一层
  - 第二层缩进
    - 第三层缩进
```

#### 有序列表

```markdown
1. 步骤一
2. 步骤二
   1. 子步骤 2.1
   2. 子步骤 2.2
3. 步骤三
```

#### 任务清单

```markdown
- [x] 已完成的任务
- [ ] 待完成的任务
- [ ] 另一个待办项
```

### 5.6 分隔线与标题层级

```markdown
<!-- 分隔线 -->
---
或
***

<!-- 标题层级（一篇帖子只用一次 H1） -->
# 一级标题（帖子标题，自动生成，无需手写）
## 二级标题（主要章节）
### 三级标题（子章节）
#### 四级标题（细节分类）
##### 五级标题（慎用，通常不需要）
###### 六级标题（极少使用）
```

## 六、标签使用指南

| `配置问题` | settings/config 相关 |

| 标签 | 适用场景 |

| `讨论` | 一般性话题讨论 |

### 6.2 标签命名规范

| 规范 | 说明 | 示例 |
|------|------|------|
| **中文标签** | 面向中文用户的通用概念 | `新手入门`, `性能优化`, `经验分享` |
| **英文标签** | 技术术语、专有名词 | `bug`, `API`, `TypeScript`, `WebSocket` |
| **混合使用** | 中文场景 + 英文技术词 | `AI补全`, `Python配置`, `Git集成` |
| **小写优先** | 英文标签统一小写 | 用 `plugin` 不用 `Plugin` |
| **连字符连接** | 多个单词用 `-` 连接 | `code-completion`, `team-collab` |
| **避免空格** | 中文标签内部不含空格 | 用 `账号安全` 不用 `账号 安全` |

### 6.3 标签数量建议

| 数量 | 建议 |
|------|------|
| **2 个** | 最精简，适用于主题明确的帖子 |
| **3-4 个** | **推荐**，覆盖主要维度且不过度 |
| **5 个** | 上限，适用于跨多个领域的内容 |
| **>5 个** | 不推荐，会稀释标签的检索价值 |

#### 标签选择策略

1. **一个类型标签**：标识帖子类型（`bug` / `功能请求` / `求助` / `经验分享`）
2. **一个领域标签**：标识涉及的技术/功能领域（`AI功能` / `Python` / `UI设计`）
3. **一个场景标签**：标识使用场景或平台（`macOS` / `团队协作` / `新手入门`）
4. **可选版本标签**：针对特定版本的讨论（`v2.1`, `beta`）

## 七、发布前自检清单

在提交任何帖子到 TRAE 论坛之前，按此清单逐项确认：

### 📋 内容质量检查（5项）

- [ ] **标题不含泛化词**
  - ❌ 不好的例子：「求助」、「有个Bug」、「一个问题」、「大家帮我看下」
  - ✅ 好的例子：「【Bug 反馈】TRAE 自动保存丢失代码改动（macOS Sonoma + Next.js 项目）」
  - **规则**：标题必须让读者仅看标题就能判断帖子大概讲什么

- [ ] **环境信息完整**
  - 产品建议：影响范围数据（用户规模/频率估算）
  - Bug 反馈：≥2 项具体环境数据（TRAE 版本/OS/Node/项目类型）
  - 求助提问：运行环境描述
  - **最低要求**：至少包含 2 项可验证的具体信息

- [ ] **复现步骤清晰**
  - 编号列表格式（`1.` `2.` `3.`）
  - 每步一个明确动作
  - 可由他人独立复现
  - **Bug 反馈必填**

- [ ] **目标板块正确**
  - 产品建议 → `/c/8-category/8`
  - Bug 反馈 → `/c/22-category/22`
  - 求助提问 → `/c/7-category/7`
  - 经验分享 → `/c/9-category/9`
  - Skill 创作 → `/c/37-category/37`

- [ ] **标签合理（2-5个）**
  - 类型标签（如 Skills / Skill创作 / featured）
  - 技术域标签（如 bug / auto-save / macOS）
  - 具体主题标签（1-2个）
  - **避免**：过于宽泛或完全无关的标签

### 🔧 技术检查（3项）

- [ ] **Markdown 格式无误**
  - 表格对齐正确
  - 代码块有语言标识
  - 链接可点击
  - 无裸露 HTML 标签

- [ ] **无敏感信息泄露**
  - 无真实密码/token/私钥
  - 无内部 IP 或非公开服务地址
  - 用户名/公司名如涉及隐私可用占位符替代

- [ ] **长度适中**
  - 正文建议 300-3000 字符
  - 过短（<100字）：信息不足，社区难以回应
  - 过长（>5000字）：重点被淹没，考虑拆分多帖

### 💡 最后一步（2项）

- [ ] **通读一遍全文**
  - 以陌生读者视角阅读
  - 检查是否有歧义或遗漏
  - 确认语气尊重且专业

- [ ] **保存本地副本**
  - 发帖前将内容存入草稿 `~/.trae/forum-drafts/`
  - 避免发布意外导致内容丢失
