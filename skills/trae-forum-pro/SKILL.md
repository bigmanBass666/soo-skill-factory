# TRAE Forum Pro — 论坛社区全能助手

## 1. Skill 概述

本 Skill 是 TRAE 官方论坛 (https://forum.trae.cn/) 的智能社区助手，覆盖四大核心能力：**智能搜索**（从海量帖子中精准定位答案）、**帖子撰写**（按规范生成高质量帖子内容）、**趋势洞察**（追踪社区热点和官方动态）、**互动管理**（草稿跟踪、回复辅助、发布流程）。无论用户是想"去论坛找个方案"、"帮我写个规范帖子"，还是"看看社区最近在讨论什么"，统一由本 Skill 接管处理。

## 2. 触发场景

以下任一场景出现时，立即激活本 Skill：

1. **答案检索** — 用户提到"在论坛搜一下""找找有没有人遇到过这个问题""社区里有没有解决方案"
2. **帖子撰写** — 用户要求"帮我写个帖子""我要反馈一个 Bug""想提个产品建议"
3. **趋势查询** — 用户问"最近论坛热门话题是什么""大家都在讨论什么新功能"
4. **官方动态** — 用户想了解"官方最新公告""管理员说了什么""版本更新动态"
5. **格式化需求** — 用户有草稿但不确定"这个帖子格式对不对""标签怎么选""标题怎么写更好"
6. **草稿管理** — 用户需要保存/恢复/编辑论坛草稿
7. **回复辅助** — 用户想"帮我回个帖子""引用原帖怎么写"
8. **隐含场景** — 用户描述的问题明显属于社区讨论范畴（如"别人是怎么解决 X 的"），即使未提"论坛"二字
9. **竞品对比** — 用户想知道"论坛上大家怎么评价 X 功能 vs Y 方案"
10. **版本问题排查** — 用户遇到疑似已知问题，需要确认是否已有社区解决方案
11. **新人引导** — 用户首次接触 TRAE 社区，需要发帖指南或板块介绍
12. **数据汇总** — 用户需要某类话题的帖子统计或趋势报告

## 3. 模块 A：智能搜索助手

### 工作流

```
关键词提取 → 板块定位 → 帖子筛选 → 内容提取 → 对比摘要
```

**步骤详解：**

1. **关键词提取**
   - 从用户自然语言中抽取核心技术词（如错误码、功能名、报错信息）
   - 扩展同义词和变体（如 "热更新" ≈ "HMR" ≈ "hot reload"）
   - 保留原始错误片段用于精确匹配

2. **板块定位**
   - 根据关键词特征判断最可能出现的板块：
     - 报错/崩溃 → 「Bug 反馈」
     - 功能请求 → 「产品建议」
     - 使用疑问 → 「使用交流」或「问答」
     - 配置/部署 → 「开发技巧」
   - 若无法确定，优先搜索全站再按板块过滤

3. **帖子筛选**
   - 使用 WebFetch 访问 forum.trae.cn 的搜索接口或板块页面
   - 按「回复数 × 浏览量」加权排序（高互动 = 高价值）
   - 过滤已关闭/已解决的旧帖（除非用户明确要求历史数据）
   - 标记包含官方/管理员回复的帖子为优先结果

4. **内容提取**
   - 对每个命中帖子提取：楼主问题描述 + 官方回答（如有）+ 最高赞社区方案 + 解决状态标记
   - 跨帖子对比相同问题的不同解法，标注优劣

5. **对比摘要**
   - 将多帖信息合并为一份结构化报告
   - 给出推荐操作路径

### 输出格式：结构化搜索报告

```markdown
## 🔍 搜索报告：{用户查询关键词}

### 匹配帖子（按相关性排序）

**帖子 #1：[帖子标题](URL)** (📊 34 回复 / 512 浏览 / ★★★★★ 相关性 / ✅ 已解决 / Bug反馈)
> 一句话概括该帖核心内容与用户查询的匹配度

**帖子 #2：[帖子标题](URL)** (📊 5 回复 / 128 浏览 / ★★★★☆ 相关性 / 🔄 讨论中 / 使用交流)
> 一句话概括该帖核心内容与用户查询的匹配度

### 关键信息提取

**帖子 #1：[标题]** (📊 34 回复 / 512 浏览)
- **问题描述**：{一句话概括楼主的核心问题}
- **官方回答**：{管理员/官方账号的回复摘要，无则标注"暂无"}
- **社区推荐方案**：{获赞最多的非官方回复} [已验证]/[社区推荐]/[理论方案]
- **解决状态**：✅ 已解决 / 🔄 部分解决 / ❌ 未解决 / ⏳ 待确认
- **评分理由**：{一句话说明为什么给这个相关性星级，如"精确匹配错误码+有完整解决方案"}

### 方案对比（当多个帖子解决同一问题时必填）

| 维度 | 帖子#1 方案 | 帖子#2 方案 | 评价 |
|------|------------|------------|------|
| 可靠性 | {高/中/低} | {高/中/低} | {哪个更可信，为什么} |
| 操作难度 | {简单/中等/复杂} | {简单/中等/复杂} | {哪个更容易上手} |
| 适用场景 | {适用条件} | {适用条件} | {不同场景推荐不同方案} |

### 推荐操作路径

1. **首选方案**：参考帖子 #1 的社区推荐方案 → {具体步骤}
2. **备选方案**：若上述无效，尝试帖子 #2 中提到的 {方法}
3. **进一步行动**：若均无效，建议发新帖并附上已尝试记录
```

### 无结果时的处理策略

- 不要直接说"没找到"，而是：
  - 放宽关键词重新搜索（去掉修饰词、换用同义词）
  - 搜索相邻板块（如从「Bug 反馈」扩展到「使用交流」）
  - 推荐用户发新帖，并自动调用**模块 B** 生成规范的求助模板
  - 提供类似问题的相关帖子作为参考线索

### 自动补全逻辑

检测用户输入后，对照各类型的必填字段逐一检查：

| 缺失字段 | 检测信号 | 补全动作 |
|----------|----------|----------|
| 环境信息 | 无版本号/OS 信息 | 询问用户当前 TRAE 版本和系统 |
| 复现步骤 | Bug 帖子缺少步骤编号 | 引导用户按 1-2-3 格式补充 |
| 已尝试方案 | 求助帖无"试过"相关表述 | 提醒用户列出已排除的方案 |
| 痛点数据 | 产品建议缺乏量化描述 | 引导补充影响范围和使用频率 |
| 效果证据 | 分享帖无 Before/After | 建议添加对比数据或截图 |

**补全原则**：先一次性列出所有缺失字段（不要逐个追问），提供默认值供用户确认或修改。

## 6. 模块 D：互动管理工具

### 草稿管理

草稿存储路径：`~/.trae/forum-drafts/`

**操作命令映射：**

| 用户意图 | 文件系统操作 | 文件命名规则 |
|----------|-------------|-------------|
| 保存当前草稿 | 写入 `{type}-{timestamp}.md` | type ∈ {suggestion, bug, question, share} |
| 列出所有草稿 | 读取目录，按修改时间倒序展示 | — |
| 恢复指定草稿 | 读取文件内容，加载到编辑上下文 | — |
| 删除草稿 | 删除对应文件 | — |

**草稿文件头部模板：**

```yaml
---
title: "{草稿标题}"
type: {suggestion|bug|question|share}
status: draft
created: {ISO 8601}
target_board: {目标板块}
tags: [{标签列表}]
---
{帖子正文内容}
```

### 帖子跟踪

维护用户已发布的帖子记录：

- **存储位置**：`~/.trae/forum-drafts/published.json`
- **记录结构**：

```json
{
  "posts": [{
    "title": "帖子标题",
    "url": "https://forum.trae.cn/t/xxx",
    "type": "bug",
    "published_at": "2025-01-15T10:30:00Z",
    "board": "Bug 反馈",
    "replies": 0,
    "status": "tracking"
  }]
}
```

- **状态检查流程**：通过 WebFetch 访问已发布帖子 URL，解析当前回复数和时间线，与上次记录对比，若有新回复则通知用户。

### 回复辅助

当用户需要回复他人帖子时，按以下流程处理：

1. **读取原帖**：通过 URL 获取原帖完整内容
2. **生成引用块**：`> **引用自 [@原作者](原帖URL)**：{关键段落}`

3. **构建回复框架**：

```markdown
> **引用自 [@原作者](原帖URL)**：{关键段落}

{回复正文}

--- 如有帮助欢迎点赞 👍 有疑问请继续讨论
```

**回复质量原则**：先确认理解对方问题 → 给出方案或代码示例 → 结尾保持开放态度邀请讨论。

### 失败回退策略

当任何网络操作失败时（发帖失败、抓取超时等）：1. **立即保存本地副本** — 将内容写入草稿目录，不丢失任何用户输入；2. **告知用户原因** — 说明是网络问题、论坛维护还是其他原因；3. **提供手动途径** — 给出论坛直接访问链接和操作指引；4. **设置重试建议** — 建议用户 N 分钟后重试，或稍后再次唤起本 Skill。

### 一键发布到论坛 (D.5)

**前置条件**：用户已确认帖子内容无误；`cookie.md` 包含有效的 TRAE 论坛 session Cookie；环境安装了 playwright 且 Chrome 可用。

**发帖板块映射：**

| 帖子类型 | 目标板块 URL |
|----------|-------------|
| 产品建议 | https://forum.trae.cn/c/8-category/8 |
| Bug 反馈 | https://forum.trae.cn/c/22-category/22 |
| 求助提问 | https://forum.trae.cn/c/7-category/7 |
| 经验分享 | https://forum.trae.cn/c/9-category/9 |
| 技能创作赛 | https://forum.trae.cn/c/37-category/37 |

**发布流程（12 步）：**

1. **Cookie 检查** — 读取 cookie.md，验证 `_forum_session` 和 `sessionid` 字段存在
2. **目标页面导航** — 根据帖子类型导航到对应板块
3. **打开编辑器** — 点击"新建话题"按钮，等待加载完成（约 2-3 秒）
4. **填写标题** — 向标题输入框输入标题
5. **确认编辑模式** — 检查编辑器是否在 Markdown 模式（底部应显示"使用 Markdown、BBCode 或 HTML 进行排版"）。如果不是，按 Ctrl+M 切换
6. **填写正文** — 点击内容区域，使用 Ctrl+V 粘贴 Markdown 内容。**重要**：粘贴后等待 2-3 秒让编辑器处理
7. **预览验证** — 检查右侧预览是否正确渲染了 Markdown（标题、代码块、表格等应正确显示）
8. **添加标签** — 通过标签选择器添加推荐标签
9. **点击发布** — 点击"创建话题"按钮
10. **处理提示** — 如果出现"帖子需要审批"提示，点击"确定"关闭
11. **验证发布** — 访问帖子 URL 确认内容完整（>100 字符）
12. **记录发布** — 将 URL 写入 published.json

**成功输出：** `✅ 发布成功！📎 标题:{title} 📎 URL:https://forum.trae.cn/t/topic/{ID} 📎 ID:#{ID} 📎 板块:{category}`

**失败回退：**

| 失败场景 | 处理策略 |
|---------|---------|
| Cookie 过期/无效 | 提示用户重新导出 Cookie，保存当前内容为草稿 |
| 编辑器未找到 (#create-topic 缺失) | 截图诊断页面状态，提示手动发帖并给出操作指引 |
| 发布超时 (20s 内无响应) | 保存草稿，返回可能的错误信息，建议稍后重试 |
| 内容验证失败 (正文<100字符) | 报告异常，建议检查 Markdown 格式是否有特殊字符 |

**Cookie 检测细节：** 来源优先级 `~/.trae/cookie.md` > `/workspace/cookie.md` > 用户直接提供；必须同时包含 `sessionid` 和 `_forum_session` 字段；过期特征为访问论坛首页后页面仍显示"登录"按钮。

**技术实现**：使用 Playwright MCP 执行；编辑器有两种模式：
- **Markdown 模式**（默认）：支持 Markdown、BBCode 或 HTML 语法，底部提示"使用 Markdown、BBCode 或 HTML 进行排版"
- **富文本编辑器模式**：按 Ctrl+M 切换，提供可视化编辑工具

**粘贴策略**：
1. 将 Markdown 内容复制到剪贴板：`cat content.md | clip`
2. 点击编辑器内容区域获取焦点
3. 使用 Ctrl+V 粘贴
4. 等待 2-3 秒让编辑器处理
5. 检查右侧预览确认格式正确

**常见问题**：
- 如果预览显示原始 Markdown 而非渲染后格式，检查是否在 Markdown 模式
- 如果粘贴超时，尝试分段粘贴或缩短内容长度
- 标题重复会导致发布失败，需要修改标题

## 7. 输出格式规范总览

所有模块输出遵循统一的格式约定：

| 输出类型 | 格式要求 | 使用场景 |
|----------|----------|----------|
| 搜索报告 | Markdown 表格 + 结构化章节 | 模块 A 结果输出 |
| 帖子草稿 | 完整 Markdown + YAML frontmatter | 模块 B 生成内容 |

- 外部链接一律使用 `[文字](URL)` 格式并确保可点击
- 代码片段标注语言类型以启用语法高亮
- 长内容使用折叠细节 `<details>` 保持主界面整洁

## 8. 最佳实践与论坛礼仪

### 高效沟通六条原则

1. **先搜索再发帖** — 在撰写新帖之前，先通过模块 A 搜索是否有相同或相似问题。重复帖子分散社区注意力，降低每个人获得帮助的概率。

2. **一个好标题胜过十段描述** — 标题是帖子的门面。包含关键技术词和核心现象的标题能让对的人快速发现你的帖子，也能让搜索结果更准确。

3. **用数据说话** — 在产品建议中提供频率估算和影响范围，在 Bug 反馈中给出完整的环境信息和复现步骤，在分享中展示 Before/After 对比。量化信息让读者快速判断相关性。

4. **标记解决状态** — 问题解决后回到自己的帖子回复并说明最终方案，帮助后来者。这既是社区礼仪，也是对自己知识的一次梳理。

5. **建设性地参与讨论** — 不同意对方观点时，针对论点而非人身；提出替代方案时解释为什么它更好；感谢每一个提供帮助的人，无论方案是否最终有效。

6. **善用标签系统** — 准确的标签让帖子被更多人看到，错误的标签让帖子石沉大海。每帖选择 2-4 个标签，覆盖类型 + 技术域 + 具体主题三个维度。

### 发帖前自检清单

在提交任何帖子之前，依次确认以下项：

- [ ] **标题测试**：只看标题，陌生人能否判断帖子大概讲什么？
- [ ] **搜索验证**：论坛中是否已有高度相似的帖子？（如有，考虑跟帖而非新开）
- [ ] **字段完整**：所选帖子类型的所有必填字段都已填写？
- [ ] **信息准确**：版本号、错误日志、复现步骤都经过核实？
- [ ] **标签合适**：选择的标签能帮助目标读者找到这篇帖子？
- [ ] **语气恰当**：没有情绪化表达？对官方团队保持尊重但可以直率？
- [ ] **可操作性**：读者看完帖子后知道该做什么吗？
